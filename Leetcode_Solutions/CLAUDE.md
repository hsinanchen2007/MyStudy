## 1. 這個資料夾是什麼

這是一個龐大的 **LeetCode 題解集**。最上層每個資料夾代表一道 LeetCode 題目
(約 **1,596** 題)。每道題目底下,同一個問題用多種**程式語言**求解;每個語言資料夾
內又包含許多種不同的解法,這些解法原本是從 LeetCode 討論區貼文抓下來的
(Markdown 格式)。

### 目錄結構

```
Leetcode_Solutions/                         <- 專案根目錄(本資料夾)
├── CLAUDE.md                               <- 本檔
├── <題目代稱-中文題名>/                     <- 每題一個資料夾(約 1,596 個)
│   ├── question.txt                        <- 題目敘述(類 HTML 內容);非程式碼,完全未被更動
│   └── answer-level{1,2,3}/                <- 難度/分類層(每題剛好一種)
│       └── <語言>/                          <- 語言資料夾(見下方對應表)
│           └── <解法標題>.<副檔名>          <- 單一解法檔(原本全是 *.txt)
└── ...
```

- 題目敘述檔(`question.txt`)位於**第 2 層**,下述所有作業**都不會**更動它。
- 解法檔位於**第 4 層**:`<題目>/answer-levelN/<語言>/<檔案>`。
- 解法檔總數:**113,522** 個。

### 作業二 — 將 Markdown 敘述文字註解掉(「策略 A」)

抓下來的檔案其實是 **Markdown 貼文**:中文說明文字 + 一個或多個程式碼圍欄區塊
(```` ```語言 … ``` ````)。維持原樣的話,敘述文字與圍欄標記都不是合法原始碼,
因此檔案無法編譯/提交。

**策略 A = 保留全部、就地註解。** 對每個檔案:
- 圍欄區塊**內**的行 → 原樣保留(真正的程式碼)。
- 圍欄區塊**外**的行(敘述)→ 在行首加上該語言的行註解符號。
- 圍欄標記(```` ``` ````)本身 → 也一併註解(保留資訊,不刪任何東西)。
- 多解法檔會保留**全部**程式碼區塊。
- 沒有圍欄的檔案 → 採保守啟發式:只把開頭的中文敘述段落,以及落單的單/雙反引號行
  註解掉;從第一行真正的程式碼起,其餘全部原樣保留。

#### 各語言的註解符號

| 註解符號 | 適用語言 |
|---|---|
| `// ` | cpp, c, java, csharp, javascript, golang, swift, rust, scala, kotlin, php |
| `# `  | python3, python, ruby, bash |
| `-- ` | mysql, oraclesql, mssql(注意:MySQL 規定 `--` 後必須有空白) |

## 5. 已知限制

- **多解法檔無法直接編譯。** 策略 A 刻意保留每個程式碼區塊,因此含 N 個解法的檔案
  會有 N 份 `class Solution`(或等價物)。這是預期行為,不是 bug。後續可再跑一道
  處理:只保留第一個/最大的區塊為活碼,其餘註解掉。
- **無圍欄與奇數圍欄檔為盡力處理。** 程式碼之後的尾段敘述(罕見)可能仍未被註解;
  若某個特定檔案編譯失敗,請對照待複查清單檢視。
- **`python` 與 `python3`** 都產生 `.py`;**三種 SQL 方言**都產生 `.sql` —— 原本的
  方言只能從上層資料夾名稱來區分。
